# Wedding invite redesign — TDD tracking

Этот каталог фиксирует пошаговый план редизайна свадебного лендинга. Каждый шаг — отдельная проверяемая задача с TDD-подходом: сначала критерии и тесты, затем реализация, затем рефакторинг/визуальная доводка.

## TDD-цикл для каждого шага

1. **Red** — зафиксировать ожидаемое поведение в тестах/чеклисте до реализации.
2. **Green** — реализовать минимально достаточное решение, чтобы тесты и критерии прошли.
3. **Refactor** — улучшить визуал, структуру CSS/React, не ломая тесты.
4. **Visual QA** — проверить вручную в браузере на mobile/desktop.
5. **Regression** — прогнать общие команды проверки.

## Общие команды проверки

```bash
npm run typecheck
npm run test:unit
npm run build
npm run test:smoke
```

Для локального визуального просмотра:

```bash
npm run dev
```

Открыть:

```text
http://localhost:3000
```

> Важно: перед `npm run test:smoke` порт `3000` должен быть свободен. Если запущен `npm run dev`, остановить его через `Ctrl + C`.

## Definition of Done для всего редизайна

- [ ] Первый экран выглядит как премиальное свадебное приглашение.
- [ ] Закрытый конверт визуально ровный, симметричный, без «кривой» геометрии.
- [ ] Кнопка «Открыть приглашение» заметная и красивая.
- [ ] По клику конверт открывается, письмо выезжает, текст читаемый.
- [ ] После скролла пользователь видит отдельную секцию детских полароидов.
- [ ] Музыка управляется только маленькой кнопкой в правом верхнем углу.
- [ ] Нет горизонтального скролла на 360/390/820/1440 px.
- [ ] `prefers-reduced-motion` показывает рабочую статичную/быструю версию.
- [ ] Все интерактивные элементы доступны с клавиатуры.
- [ ] Все команды проверки проходят.

## Правила обновления статуса

После завершения каждого шага обновлять:

1. статус в таблице выше;
2. чеклист в соответствующем `PLAN.md`;
3. список добавленных/изменённых тестов;
4. результаты команд проверки.
